# ADR-0021: 設定ファイルにおける相対パスの解決

## ステータス

Accepted

## コンテキスト

ADR-0016 で導入した設定ファイル方式では、`watch_dir` や `background_image` のパス指定において `~`（ホームディレクトリ展開）と絶対パスのみが安定して動作していた。相対パスを記述した場合、プロセスのカレントディレクトリ基準で解決されるため、アプリの起動方法（ダブルクリック / ターミナル / 異なるディレクトリからの実行）によって結果が変わり不安定だった（#26）。

## 決定

### 相対パスを設定ファイルの配置ディレクトリ基準で解決する

`resolve_path` ヘルパーを導入し、パス文字列を以下の順序で処理する:

1. `~` で始まる場合は `shellexpand::tilde` でホームディレクトリに展開する
2. 展開後のパスが絶対パスの場合はそのまま使用する
3. 展開後のパスが相対パスの場合は、設定ファイルの親ディレクトリを基準に `join` して解決する

### 対象フィールド

- `watch_dir`
- `background_image`
- 将来追加されるパス型の設定項目も同様に `resolve_path` を通す

### 例

`~/apps/ndp/ndp.config.json` に以下を記述した場合:

```jsonc
{
  "watch_dir": "./data",
  "background_image": "../images/bg.png"
}
```

- `watch_dir` → `/Users/issm/apps/ndp/data`
- `background_image` → `/Users/issm/apps/images/bg.png`

## 理由

- 設定ファイルの配置ディレクトリを基準とした理由: 設定ファイルとデータを同じディレクトリにまとめて配布するユースケース（ポータブル構成）を想定。設定ファイルの位置はルックアップで確定しているため、基準として安定している
- カレントディレクトリ基準としない理由: アプリの起動方法によって結果が変わり予測不能。特に `.app` バンドルをダブルクリックした場合、カレントディレクトリは `/` になることがある
- `canonicalize` を使わない理由: パスが存在しない段階でも解決できる必要がある（`watch_dir` は未存在なら自動作成するため）

## 影響

- 既存の絶対パスや `~` 付きパスの動作は変わらない（後方互換性あり）
- 相対パスが使えるようになったことで、設定ファイルとデータを同じディレクトリにまとめたポータブル配布が容易になる
