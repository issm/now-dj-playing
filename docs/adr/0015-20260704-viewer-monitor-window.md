# ADR-0015: `m` キーによるモニタウィンドウの追加

## ステータス

Accepted

## コンテキスト

DJ プレイ中に viewer ウィンドウを iPad (Sidecar) 経由で聴衆側に向けて運用した際、DJ 本人側から「現在何が表示されているか」を確認できない課題があった。

## 決定

### Tauri 2 マルチウィンドウでモニタウィンドウを追加

- メインウィンドウで `m` キーを押すとモニタウィンドウを開く
- CLI オプション (`--enable-monitor`) は採用しない（ランタイムで必要に応じて開けば十分）

### モニタウィンドウの仕様

| 項目 | 内容 |
|---|---|
| ウィンドウラベル | `"monitor"` |
| サイズ | 480×320（リサイズ可） |
| 常に前面 | always on top |
| 最大数 | 1（既に開いている場合はフォーカスのみ） |
| 閉じ方 | ウィンドウのクローズボタン（`m` キーはトグルしない） |
| メインへの影響 | なし（モニタを閉じてもアプリは続行） |

### Rust 側の実装

- `open_monitor` Tauri コマンドを追加
- `WebviewWindowBuilder` でラベル `"monitor"` のウィンドウを動的に生成
- 既存ウィンドウがあれば `get_webview_window("monitor")` でフォーカスのみ
- capabilities に `"monitor"` ウィンドウを追加

### React 側の実装

- `getCurrentWebviewWindow().label` でウィンドウ種別を判定
- `"monitor"` ラベルの場合は `MonitorView` コンポーネント（コンパクト表示）を描画
- モニタウィンドウでもメインと同じ `track-changed` イベントを受信（Tauri の emit はグローバル）
- メインウィンドウのみで `start_watch` を invoke
- ショートカット処理もメインウィンドウのみに限定

### MonitorView のレイアウト

- アートワークサムネイル（80×80）+ タイトル・アーティスト・アルバムを横並び
- テキストは truncate で省略表示
- DJ 情報やコメントは省略（コンパクト優先）

## 理由

- CLI オプションではなく `m` キーとした理由: 起動後に必要に応じて表示すれば十分であり、起動フラグの管理が不要になる
- always on top: DJ 操作中に他ウィンドウの後ろに隠れないため
- 最大1ウィンドウ: 複数開く意味がなく、リソースの無駄を防ぐ
- `m` キーをトグルにしない理由: 誤操作でモニタが消えるとプレゼン中に困る。閉じたい場合は明示的にクローズボタンを使う

## 影響

- Tauri の emit がグローバルであるため、モニタウィンドウは特別な IPC なしでトラック情報を受信できる
- 将来モニタウィンドウの表示内容をカスタマイズしたい場合は `MonitorView` コンポーネントを変更する
- ショートカットオーバーレイに `m` が追加された
