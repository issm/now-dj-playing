# ADR-0005: Publisher CLI ツール

## ステータス

Accepted

## コンテキスト

DJ ソフトで再生中の楽曲情報を共有ディレクトリに書き出す仕組みが必要。楽曲ファイル (mp3/m4a) からタグ情報とアートワークを抽出し、ADR-0002 で定めたプロトコルに従ってファイルを出力する。

## 決定

### CLI ツールとして実装

`apps/publisher` に `ndp-publish` コマンドを配置する。

```sh
ndp-publish --file /path/to/track.mp3 --out /path/to/shared/ --id dj-alpha --dj-name "DJ Alpha"
```

### オプション

| オプション | 必須 | デフォルト | 説明 |
|---|---|---|---|
| `--file` | ✓ | - | 楽曲ファイルパス (mp3, m4a) |
| `--out` | ✓ | - | 出力先ベースディレクトリ |
| `--id` | - | `dj-000` | DJ ディレクトリ名 |
| `--dj-name` | - | - | DJ 名 (テキスト) またはロゴ画像パス |

出力先は `{out}/{id}/` となる。

### タグ読み取りライブラリ

- MP3: `id3` クレート
- M4A: `mp4ameta` クレート

当初 `lofty` を採用したが、一部楽曲ファイルの壊れた UTF-16 タグで Relaxed モードでもエラーが発生したため、`id3` + `mp4ameta` に切り替えた。既存プロジェクト (djay-audio-loader) で実績のある組み合わせ。

### DJ プロファイル (`--dj-name`)

- 値が既存の画像ファイルパス (png/jpg/jpeg) → `dj-profile.{ext}` としてコピー
- それ以外 → `dj-profile.txt` としてテキスト出力
- 指定なし → プロファイルは書き出さない（既存があればそのまま残る）

### 出力フロー

1. `{out}/{id}/` ディレクトリを作成
2. `--dj-name` があれば `dj-profile` を書き出し
3. 楽曲ファイルからタグを読み取り
4. アートワークがあれば `artwork.{ext}` を書き出し
5. `now_playing.json` を書き出し
6. `.ready` を書き出し（最後）

## 理由

- Rust CLI として実装することで、watch-core と同じ型定義・スキーマに対する整合性を保てる
- `id3` + `mp4ameta` は対象フォーマット (mp3/m4a) に特化しており、堅牢なパース実績がある
- `--id` のデフォルト値 (`dj-000`) により、viewer 側の `VITE_DEFAULT_DJ_ID` と対応させやすい

## 影響

- viewer 側は `VITE_DEFAULT_DJ_ID` で監視対象の DJ ディレクトリを指定する（デフォルト `dj-000`）
- publisher と viewer で `--id` / `VITE_DEFAULT_DJ_ID` を合わせる必要がある
