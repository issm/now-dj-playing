# ADR-0008: ベースディレクトリ監視と DJ ID フィルタリング

## ステータス

Accepted

## コンテキスト

従来は `{base_dir}/{dj_id}/` を直接監視していたため、起動時に DJ ディレクトリが存在しない場合（publisher がまだ一度も実行されていない等）にエラーで監視を開始できなかった。

## 決定

### ベースディレクトリを再帰監視する

- 監視対象を `{base_dir}/` に変更し、`RecursiveMode::Recursive` で配下全体を監視する
- ベースディレクトリが存在しなければ自動作成する (`mkdir -p` 相当)
- `.ready` の変更イベント発生時に `state.dir_name == dj_id` でフィルタリングし、対象 DJ のイベントのみフロントに emit する

### 起動時の既存データスキャン

`{base_dir}/{dj_id}/` が存在し `.ready` があれば従来通り即座に emit する。存在しなければスキップし、後からディレクトリが作られた時点で検知する。

## 理由

- publisher が `--out {base_dir} --id {dj_id}` で実行されると `mkdir -p` でディレクトリを作成してファイルを書き出す。viewer がベースディレクトリを監視していれば、ディレクトリ作成後の `.ready` 書き込みを検知できる
- 起動順序に依存しない設計（viewer 先起動 → publisher 後起動でも動作する）

## 影響

- ベースディレクトリ配下の全変更イベントを受け取るため、対象外の DJ ディレクトリのイベントも `notify` から通知される（DJ ID フィルタで無視する）
- 将来的に複数 DJ を同時表示する場合は、フィルタ条件を拡張すればよい
